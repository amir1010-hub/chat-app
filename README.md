# Telegram Web в окне через GitHub Codespaces

Корневая страница содержит окно Telegram Web A. HTML, JavaScript, workers, ресурсы и MTProto WebSocket/HTTP обслуживаются через HTTPS-адрес запущенного Codespace на порту 3000. GitHub Pages не запускает этот сервер.

## Запуск

1. Создайте Codespace для ветки `telegram-relay-codespaces`.
2. Выполните `bash start.sh`.
3. Откройте адрес порта 3000. Для друзей переключите видимость только этого порта в **Public**.

Сборка стороннего клиента и собственные Telegram API credentials не требуются: сервер проксирует опубликованный официальный веб-клиент, добавляя маршрутизацию сетевых запросов через свой origin. Пользователи входят в собственные Telegram-аккаунты в окне клиента. Сервер не хранит Telegram-сессии и не журналирует содержимое MTProto, номера, коды или сообщения. Сессия веб-клиента хранится в браузере посетителя.

`GET /__health` проверяет gateway. Прямой запрос к `/tgproxy/http/2` позволяет проверить MTProto HTTP transport; WebSocket доступен по `/tgproxy/ws/2`. Разрешены только хосты `web.telegram.org` и его непосредственные поддомены. Публичный сервер не является произвольным HTTP-прокси.

## Ограничения

- Codespace должен работать; остановленный Codespace не обслуживает ссылку. Это временный стенд, который расходует квоты Codespaces.
- CSP ограничивает сетевые соединения origin сервера. WebRTC-звонки отключены, чтобы не создавать прямые соединения в обход relay. Внешние сайты, открытые пользователем по ссылке, работают отдельно.
- Официальный веб-клиент обновляется без привязки к этой ветке. Изменение сетевого транспорта Telegram может потребовать обновления маршрутизации. На стороннем домене отдельные PWA-функции и синхронизация с официальным сайтом могут быть недоступны.
- Это неофициальное размещение. Владелец любого прокси, отдающего JavaScript веб-клиента, технически может изменить клиентский код; используйте только доверенное размещение.
