# Telegram Web via GitHub Codespaces — эксперимент

> **НЕ GitHub Pages.** Весь основной MTProto WebSocket/HTTP трафик проходит через работающий Codespace: браузер → HTTPS/WSS `*.app.github.dev` → прокси-шлюз → Telegram. Звонки WebRTC и отдельные внешние ресурсы могут быть исключением.

## Запуск с телефона

1. Откройте репозиторий и перейдите на ветку **telegram-relay-codespaces**.
2. Перейдите в [создание Codespace](https://codespaces.new/amir1010-hub/chat-app/tree/telegram-relay-codespaces), выберите эту ветку.
3. Откройте терминал в Codespaces и выполните `bash start.sh`.
4. При первом запуске введите `api_id` и `api_hash` Telegram-приложения с https://my.telegram.org (не делитесь ими в чате). Скрипт сохранит их в игнорируемом .env.
5. Дождитесь сообщения **Gateway ready on port 3000**. На вкладке **Ports** откройте URL порта **3000** (оставьте **Private**).

## Что именно размещено
- **.devcontainer/** — Node 22, порт 3000.
- **start.sh** — загрузка фиксированной ревизии стороннего форка Telegram Web A, сборка клиента и запуск relay+gateway.
- **gateway/** — отдаёт готовую страницу и пересылает /tgproxy/* локальному relay.
- Форк: https://github.com/cozgerest/tg-web-relay, зафиксирован на `5341468037ce8ae0760dfe0cb1988e9a814a2e44`.

## Ограничения и безопасность
- Код внешнего форка не прошёл независимый аудит. **Не входите в основной Telegram-аккаунт до проверки кода.**
- API credentials и локальные браузерные сессии следует защищать. Не публикуйте .env. При ручном запуске credentials вводятся в Codespaces, а не через ChatGPT.
- Это тестовый стенд: Codespaces останавливаются при бездействии, расходуют квоты и **не являются надёжной постоянной прокси-инфраструктурой**. Запустить Codespace и получить временный URL можно только в вашей сессии GitHub.
- Порт **Private** не предназначен для общего доступа; режим Public требует отдельной оценки безопасности.
- GitHub Pages (статический хостинг) не может проксировать WebSocket/HTTP в реальном времени.
